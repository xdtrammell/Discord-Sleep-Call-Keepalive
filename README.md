<h1 align="center">Sleep Call Keepalive</h1>

<p align="center"><strong>Stay connected through the quiet hours.</strong><br>A tiny, open-source Windows utility for Discord voice calls that tend to disconnect after long periods of computer inactivity.</p>

If your Discord sleep call drops after roughly five hours of silence, even though both people were still there, this utility tests one likely culprit: **extended Windows input inactivity**. It occasionally sends an F15 key event while you are idle and Discord is running. It does not touch the microphone or modify Discord.

One real user's setup remained connected for several consecutive nights, with 20 successful automatic keepalive events logged after a bug fix. That is useful field evidence, not a guarantee that every disconnect has the same cause. This utility cannot fix network loss, server-side call limits, a sleeping PC, or Discord changes.

## At a glance

| | Behavior |
|---|---|
| **No mic tricks** | Your selected microphone, mute state, and TV audio stay untouched. |
| **No always-on process** | Windows Task Scheduler runs a quick check every 15 minutes, then the process exits. |
| **Only when idle** | F15 is sent after at least 165 minutes of Windows keyboard/mouse inactivity. |
| **Game-aware by default** | Normal gameplay input resets the idle clock; Windows-reported full-screen Direct3D and presentation mode also suppress events. |
| **Easy to inspect** | Source code, editable settings, on-demand diagnostics, and a timestamped log are included. |
| **No account or network access** | The program makes no network requests and has no telemetry. |

## Install

1. Download the ZIP under [Releases](https://github.com/xdtrammell/Discord-Sleep-Call-Keepalive/releases/latest). The separately linked “Source code” ZIP is generated by GitHub and does not replace the named release package.
2. Extract it to a normal folder. Do not run `Install.cmd` from inside the ZIP preview.
3. Double-click **Install.cmd**. No administrator rights, AutoHotkey, separate .NET SDK, or maintained games list are required on a typical 64-bit Windows 10/11 installation.
4. Run **Check Status.cmd**. The line `Native INPUT size: 40 bytes (expected 40)` confirms the native input layout.
5. Run **Test F15 Input.cmd** once when you are not gaming. It should report `Manual F15 input test succeeded.`

The installer compiles the included C# source locally using Windows PowerShell's built-in `Add-Type`, tests the result, and registers a task named `Discord Sleep Call Keepalive` for your signed-in Windows account. Re-running the installer upgrades the executable and task while preserving your settings and log.

> [!IMPORTANT]
> The locally compiled executable is **unsigned**. Windows Smart App Control may block it, and Smart App Control does not provide a per-app allowlist. We do not recommend switching off a system-wide protection solely for this utility. If it is blocked on your PC, leave that protection enabled and do not use this build, or build and sign your own deployment under a policy you control. This project is not affiliated with Discord.

## How it works

```text
Windows Task Scheduler, every 15 minutes
    → Is Discord running and the desktop unlocked?
    → Has Windows reported 165+ minutes without input?
    → Is full-screen Direct3D/presentation mode inactive?
    → Is no optional blocked process running?
    → Send one F15 key-down/key-up event, log it, exit
```

Windows maintains the last-input timestamp, so the utility does not need to run continuously. The first qualifying scheduled check usually occurs between 2 hours 45 minutes and 3 hours after the last input. Windows sees the injected F15 event as input and resets its idle timer. Ordinary keyboard/mouse use also resets the timer naturally.

The utility detects a **running Discord desktop process**, not whether you are currently in a voice call. If you leave Discord open while away, it can send F15 even without a call. It recognizes `Discord.exe`, `DiscordPTB.exe`, `DiscordCanary.exe`, and `Vesktop.exe` by process name. Browser-only Discord is not supported.

## Your first night

Use Discord normally. Keep your physical microphone selected and mute it if you prefer. Leave the **computer awake**, though the display may turn off. In the morning, run **Open Log.cmd** and look for a recent `SENT` entry:

```text
2026-09-20 08:18:08 | SENT   | F15 keepalive sent after 2h 58m of genuine user inactivity.
```

If the log shows successful sends and your call stays connected past its usual disconnect point, the result supports the Windows-idle explanation. If you still disconnect, check whether the PC slept, the task ran, or the call ended for another reason. A `SENT` entry only confirms Windows accepted the input, not that Discord acknowledged it or remained in the call.

## Settings and controls

Installed files are in `%LOCALAPPDATA%\DiscordSleepCallKeepalive`. Edit `settings.ini` with Notepad; changes take effect on the next scheduled run:

```ini
Enabled=true
IdleThresholdMinutes=165
SkipWhenFullScreen=true
LogSkippedRuns=false
```

The threshold accepts 30 to 240 minutes. Leave the default for the first few nights. `LogSkippedRuns=false` avoids a log entry every 15 minutes; events, diagnostics, and errors are still logged. The log rotates at approximately 1 MB, keeping one previous copy.

`blocked-processes.txt` is optional. You do **not** have to add games. If a particular application must never receive an F15 event, add its executable name on a line, such as `ExampleGame.exe`.

To pause without uninstalling, set `Enabled=false`, or disable the task in Task Scheduler. **Uninstall.cmd** removes the task and the entire installed folder, **including settings and logs**. Copy them elsewhere first if you want to keep them.

## Limitations

- **Not an absolute “never disconnect” guarantee.** Discord has not documented that this specific long-idle behavior is always tied to Windows input inactivity. This project does not read Discord's private internal state.
- **Windows must stay awake and signed in.** No scheduled input can run during Sleep or Hibernate or on a locked desktop. Remote Desktop, Fast User Switching, and unusual desktop sessions have not been tested.
- **Input is synthetic.** F15 normally has no visible effect, but any app with F15 bound could react. Anti-cheat software may treat synthetic input differently; the utility makes no attempt to hide it. If concerned, disable the task before gaming.
- **Full-screen detection is best effort.** Windows' user-notification-state API is not a universal detector of every borderless game or video. Normal mouse/keyboard activity is the primary reason the tool skips while you play.
- **No audio or call awareness.** It cannot tell if you are muted or in a call. It cannot keep Windows awake, repair Wi-Fi, or reconnect a dropped call.
- **No signed installer.** Smart App Control may block the unsigned executable. There is no one-app exception for Smart App Control.

## Troubleshooting

| What you see | What it means / what to try |
|---|---|
| `40 bytes (expected 40)` in Check Status | Correct native structure size for the 64-bit build. |
| No `SENT` entry | The idle threshold may not have been reached, Discord may not be running, Windows may be locked/asleep, or full-screen mode may suppress it. Run **Check Status.cmd**. |
| `ERROR  | SendInput failed with Win32 error 87` | You may still have the original pre-1.0.1 build. Install the current release over it, then run the manual test. |
| `SENT` entries, but a call still disconnects | The issue likely involves something beyond the standard Windows idle timestamp. Check Windows sleep, network interruptions, and Discord's call state. |
| Smart App Control blocks the installer or executable | This unsigned community build cannot be individually allowed through Smart App Control. See the installation note above. |

For bug reports, include Windows version, package version, relevant log lines, and whether the desktop was locked or asleep. **Remove usernames, paths, or other personal details before posting a log publicly.**

## Build and development

The release ZIP contains the complete source, install scripts, status/test shortcuts, documentation, and graphics. The `.github/workflows/windows-build.yml` workflow compiles on Windows and runs a native-layout self-test without injecting keyboard input into the CI runner.

The core is intentionally small. It uses `GetLastInputInfo` to check inactivity, `SendInput` to emit F15, and `SHQueryUserNotificationState` for best-effort full-screen suppression. No DLL injection, audio device manipulation, Discord client modification, or game process inspection is involved.
